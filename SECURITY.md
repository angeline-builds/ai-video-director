# Security Policy

## Report a security issue

Do not publish credentials, personal data, private media, directly exploitable steps, or other sensitive details in a public Issue, Discussion, or Pull Request.

Prefer GitHub's private vulnerability reporting feature on the repository's **Security** page. If private reporting is unavailable, open an Issue without sensitive technical details and ask the maintainer for a private channel.

Useful reports include:

- Instructions that could exceed user authorization or expose private media
- Prompt patterns that encourage impersonation, deceptive media, or unlicensed use
- Templates or automation that may reveal credentials, personal information, or local paths
- High-risk credential formats missed by the validation scripts

This policy covers the Skill, its reference templates, validation workflow, and repository documentation. It does not provide a security, legal, copyright, or platform-compliance warranty.

## 中文说明

请不要在公开 Issue、Discussion 或 Pull Request 中发布密钥、个人数据、私人视频、可直接利用的攻击步骤或其他敏感细节。

优先使用仓库 **Security** 页面中的私密漏洞报告功能。若该功能不可用，请只创建一条不含敏感技术细节的 Issue，请求维护者提供私密沟通方式。

适合报告的问题包括：越权或泄露私人素材的流程、可能促成冒充或误导内容的 Prompt、可能暴露密钥或本地路径的模板，以及校验脚本遗漏的高风险内容。
